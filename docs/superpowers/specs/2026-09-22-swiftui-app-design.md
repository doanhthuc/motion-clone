# Motion iPhone app (SwiftUI) — design

Date: 2026-09-22 · Status: approved; Phases 1–3 implemented ·
Sub-project 2 of 2 of `2026-09-21-vps-control-plane-api-design.md`

The API that this app consumes is sub-project 1 and has shipped (slices 1–6, live at the `motion-vps`
tunnel, `make api-smoke`). This spec covers the native iPhone app. It adds **no** API routes; where the
visual design shows something the API does not return, the app leaves it out (§1).

Visual source: the Claude Design canvas "Motion — iPhone App" (17 artboards,
`https://claude.ai/artifact/4woWRzTpygwJ3PrQi5RBEY`). Board names below are its board titles.

---

## 1. What was decided

- **Real data only.** Design elements the API does not back are left out of v1, not stubbed, and not
  added to the API first. Each becomes a later API slice only once using the app shows it is missed:

  | Design element | Why it is out |
  |---|---|
  | Frame progress ("214/444"), progress %, ETA | `run_detail` has per-stage `status` + `elapsed_sec` only |
  | `pod-job.log` tail on Run progress | No route |
  | Human run titles ("Áo dài đỏ · walk cycle") | A run has `id` (`tg-<chat>`) and `batch` only |
  | "Notify me" / "Notify when 4090 is back" | Stock watch, deferred in API spec §5.10 |
  | Telegram notify toggle in Settings | Telegram always reports; no route |
  | Pair (1:1) mode on New batch | Cross mode covers the stated use; pair is a later addition |
  | "Animated / has video" badge on Saved try-ons | The library does not record it |
  | Three-row GPU list on Rent GPU | `rent-panel` returns one RunPod option (the `.env` `GPU`) + one Vast option; changing GPU is `PUT /v1/pod/gpu` then a panel re-read (§3) |

- **Target: iOS 26+, Swift 6** (strict concurrency, `@Observable`). The user's phone runs iOS 26/27.
- **Secrets are seeded from the Mac's `.env` at build time** into a gitignored `Secrets.xcconfig`, copied
  into the Keychain on first launch; Settings shows them masked and can edit and re-test them. The free
  provisioning profile forces a reinstall from Xcode every 7 days; nothing needs retyping.
- **Structure: a Swift package for the logic + a thin SwiftUI app target generated by XcodeGen** (§2).
  Rejected: a single wizard-made Xcode project — a noisy committed `pbxproj`, tests only on a simulator,
  and nothing keeping money logic out of views.
- Unchanged from the API spec: no APNs (no paid Apple account), Telegram stays the notification channel,
  one shared run slot, the VPS is the only thing the app talks to.

## 2. Architecture

```
ios/
  project.yml              XcodeGen → MotionApp.xcodeproj (gitignored; `make ios-gen`)
  Secrets.xcconfig         gitignored; `make ios-secrets` writes it from the root .env
  MotionKit/               Swift package — no SwiftUI import
    Sources/MotionKit/
      API/                 APIClient (actor), endpoints, APIError, ETag cache
      Models/              Codable mirrors of the API's JSON
      Upload/              chunked uploader
      Money/               idempotency-key ledger, spend-call retry policy
      Stores/              one @Observable @MainActor store per area
      Secrets/             Keychain + first-launch seeding
    Sources/motion-contract/  CLI for `make ios-contract` (§6)
    Tests/MotionKitTests/  unit tests + hand-written JSON fixtures
  MotionApp/               SwiftUI views, Theme, fonts; one folder per board group
  README.md                build, install, free-provisioning notes
```

- **The server is the only source of truth.** No local database. Persisted on the phone: the Keychain
  (four secrets), the idempotency ledger (§4), and `UserDefaults` trivia (last tab).
- **`APIClient`** (an actor): base URL + `CF-Access-Client-Id` / `CF-Access-Client-Secret` +
  `Authorization: Bearer` + an explicit `User-Agent` (Cloudflare answered a POST with Python urllib's
  default UA with error 1010, 2026-09-21). Decodes `{"error": {"code", "message"}}` into
  `APIError.server(status, code, message)`; a Cloudflare HTML 403 is `APIError.accessDenied`. An ETag
  cache for `GET /v1/runs/{id}` compares weakly (Cloudflare rewrites ETags to `W/"…"` when it compresses).
- **Stores**: `RunsStore`, `RunDetailStore`, `MaterialsStore` + `Uploader`, `DraftStore`, `RunFlow`
  (Phase A → try-on → rent panel → confirm/resume), `PodStore`, `OutputsStore`, `TryonLibraryStore`,
  `SettingsStore`. Views never call `APIClient`. Every mutating call replaces the store's state with the
  server's answer; the app never computes a draft or a run itself.
- **Polling.** `RunDetailStore` polls every 5 s (API spec §5.7) only while its screen is visible and the
  scene is active (`.task` + `scenePhase`). `RunsStore` and `PodStore` refresh on appear and on
  pull-to-refresh; `PodStore` polls every 2 s only while a kill is running. When the app is closed,
  Telegram reports.
- **Look.** Dark only, the design's tokens as a `Theme` (ground `#0A0A0C`, surfaces `#141418`/`#1B1B20`/
  `#232329`, lime `#B9DD6B` for primary actions and the live state, red `#FF5C5C` for spend/error, amber
  for material warnings). Space Grotesk (UI) and JetBrains Mono (numbers, ids, prices) are bundled; both
  are SIL OFL, fine in a public repo. Tabs: Runs · Material · + (New job) · Output · Pod.

## 4. Money and errors

**The phone never decides to spend.** Every spend is exactly one tap; no retry ever becomes a new spend.

Spend calls: `confirm`, `resume`, `phase-a`, `regen` (all take an `Idempotency-Key`, API spec §5.5).

- **One key per tap.** The tap creates a UUID key, persisted (endpoint + body + key) in the idempotency
  ledger **before** the request is sent, cleared when a definitive answer arrives. A timeout, a dropped
  connection or the app being killed mid-request is resent with the **same** key — the server wrote its
  `pending` record before acting (API spec §5.8), so a replay returns the stored answer or
  `409 outcome_unknown`. On launch, a key still in the ledger is resent once, shown as "Checking the
  earlier Confirm…"; a new key is never minted for an old tap.
- **`409 stale_panel`** → re-read the rent panel, show the new price and GPU, require a new tap. Never
  an automatic re-confirm.
- **`409 outcome_unknown`** → no retry. "Couldn't tell whether the rent went through — check Pod", and
  the app switches to the Pod tab and refreshes it.
- **`503 bot_busy`** (lock timed out; nothing was recorded) → retry with the same key after 5 s, at most
  3 times, with the attempt count on screen.
- In flight, the button is disabled with a spinner. Confirm's label carries the price
  (`estimate_min / 60 × usd_per_hr` of the selected row).

**Kill** (red, confirmation dialog): `202`, then poll `GET /v1/pod` every 2 s until `kill_running` is
false. `last_kill.ok == false` with `destroy_unverified` shows a persistent red banner "Pod may still be
billing — check RunPod", cleared only by a later `GET /v1/pod` with no lease. `409` shows the server's
message.

**Migrate**: `ask` → a sheet stating that the source Network Volume is **deleted** once the copy
verifies; the button enables only after typing the target datacenter id → `migrate` with the token.
An expired or voided token (10 min, or a bot restart) is `409` and returns to `ask`.

**Other errors**

| Case | Phone shows |
|---|---|
| `401` | "Bearer token rejected" + link to Settings |
| Cloudflare HTML `403` / `1010` | "Cloudflare Access rejected the request" + link to Settings |
| `409`, `422` | The server's `message` verbatim — the text Telegram shows. `422` from the draft also highlights `missing` slots |
| `502` | "RunPod/Vast didn't answer" + Retry. Reads only (API spec §5.6) |
| `404` on a run or material | It was removed elsewhere (e.g. `/clear` in Telegram): refresh and drop it |
| Offline / timeout on a read | Keep the last data dimmed with "stale · 2m ago"; polling continues |
| `500` | Generic error with the `code` |

## 6. Testing and verification

**Free gates** (no phone, no spend):

| Target | Does |
|---|---|
| `make ios-gen` | `xcodegen generate` in `ios/` |
| `make ios-secrets` | Writes `ios/Secrets.xcconfig` from the root `.env` (`CONTROL_API_URL`, `CF_ACCESS_CLIENT_ID`, `CF_ACCESS_CLIENT_SECRET`, `CONTROL_API_TOKEN`); fails if any is empty |
| `make ios-test` | `swift test` in `ios/MotionKit` — on the Mac, no simulator |
| `make ios-build` | `xcodebuild` for the iOS simulator |
| `make ios-contract` | `motion-contract` sends **GET only** to the live API (`health`, `runs`, the newest `runs/{id}`, `pod`, `pipelines`, `draft`, `materials`, `outputs`, `tryon-library`) and decodes each with MotionKit's models. Stores nothing: run ids carry the Telegram chat id and material names are personal, and the repo is public |

Fixtures are hand-written JSON shaped on the Python serializers (`control/runs.py` `_summary` /
`run_detail`, `control/drafts.py` `DraftStore._view` / `pipeline_catalog`, `bot.py`
`_rent_panel_data` + `AppRuns.rent_panel`), with made-up ids. `ios-contract` keeps them honest.

**Required cases in `make ios-test`:**

- A transport failure on `confirm` is resent with the same `Idempotency-Key`; a ledger entry left by a
  simulated kill is resent unchanged on the next launch.
- `409 stale_panel` re-reads the panel and sends no second confirm.
- `409 outcome_unknown` is not retried; `503 bot_busy` is retried with the same key, at most 3 times.
- Kill: `202`, then polling until `kill_running == false`; `destroy_unverified` raises the banner.
- `migrate` cannot be sent without a token from `ask`.
- ETag: `304` keeps the previous state; a weak `W/"…"` match counts.
- Error decoding: the JSON envelope; a Cloudflare HTML 403 → `accessDenied`.
- Upload: 32 MB chunking of a file that is not a multiple of 32 MB; resume from `GET /v1/uploads/{id}`
  sends only the missing chunks.
- Cross build: N outfits → N × (`PATCH` + `add-to-batch`); drop → `DELETE …/batch/{digest}`.
- `guidance` can only encode the three allowed values.

**Per phase:**

- Phases 1–3: simulator, then the iPhone, against the live API (reads and free draft calls).
  `make api-smoke` first.
- Phases 4–6: first zero-spend checks, as the API slices did — stale-token confirm → `409` and no pod;
  kill with nothing live → `409`; bad migrate token → `409`. Then **one** real run (try-on + pod), only
  after the user says go, with the price quoted first; `make gpu-destroy` after; cost from
  `runpodctl billing`, not `currentSpendPerHr`.
- `motions-studio/setup/scrub-secrets.sh --check` exits 0 before every commit. `ios/Secrets.xcconfig`
  and `ios/MotionApp.xcodeproj` enter `.gitignore` in the commit that first creates them.

**Docs:** `ios/` and the `ios-*` targets are added to `CLAUDE.md` and `AGENTS.md` (kept in sync);
`ios/README.md` covers build, install, and the 7-day free-provisioning reinstall (the Keychain survives
it).
